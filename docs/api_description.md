# API конструктора опросов и тестов

*Описание эндпоинтов, запросов и ответов (FastAPI, JSON)*

## 1. Общие сведения

- **Формат.** Все запросы и ответы в JSON (кроме загрузки картинки). Названия полей в основном совпадают с названиями полей в базе данных (исключение: варианты ответа в JSON называются `options`, а в базе `question_choices`). Даты и время в формате ISO 8601 (`2026-11-03T02:50:00`).
- **Вход.** После `POST /auth/login` фронтенд хранит токен и отправляет его в заголовке `Authorization: Bearer <токен>`.
- **Анонимное прохождение.** Анонимный участник токена не имеет. Вместо него в заголовке `X-Attempt-Key` он передаёт секретный ключ попытки, полученный при её старте. Авторизованного участника сервер опознаёт по токену.
- **Доступ к формам по ссылке.** Ссылка содержит случайный `public_code` (например, `/f/k3x9a2`), чтобы форму нельзя было найти перебором номеров.
- **Картинки.** Загружаются отдельным запросом `POST /images` (multipart). Файлы раздаются по относительному адресу из поля `url` (например, `/uploads/9c1e7a52d0b64f3a.png`).
- **Проверки на сервере.** Три небольшие проверки подключаются к нужным адресам: вошёл ли пользователь, составитель ли он (`is_author`), его ли это форма, попытка или блок библиотеки. Правильные ответы тестов участнику не отдаются, пока прохождение не завершено.
- **Формат ошибок.** Тело ошибки: `{ "detail": "Текст ошибки" }`, иногда с дополнительными полями.

### Коды ошибок

| Код | Когда возвращается |
|---|---|
| **401** | Не вошёл: токена нет или он недействителен |
| **403** | Не хватает прав: неверная роль, чужая форма, чужая попытка, чужой приватный блок |
| **404** | Не найдено |
| **409** | Конфликт: форма уже опубликована, лимит попыток исчерпан, попытка уже завершена, время истекло |
| **413** | Загружаемый файл слишком большой |
| **422** | Неверные данные или форма не прошла проверку |

## 3. Подробное описание запросов

### 3.1. Регистрация и вход

#### POST `/auth/register`

Кто может: **Все**  ·  Успешный код: **201**

Регистрация нового пользователя. Роль выбирается один раз и потом не меняется: `is_author` равно true для составителя и false для участника. Пароль: не меньше 8 символов и не больше 72 байт в UTF-8 (кириллица разрешена; пароль не обрезается, а слишком длинный отклоняется).

**Тело запроса**

```json
{
  "email": "ivan@example.com",
  "password": "MyPass123",
  "name": "Иван",
  "is_author": true
}
```

**Ответ 201**

```json
{
  "id": 3,
  "email": "ivan@example.com",
  "name": "Иван",
  "is_author": true
}
```

**Ошибки**

- 409: пользователь с таким email уже есть
- 422: неверные данные (пустое имя, пароль короче 8 символов или длиннее 72 байт и т. п.)

#### POST `/auth/login`

Кто может: **Все**  ·  Успешный код: **200**

Вход по email и паролю. Токен фронтенд сохраняет и отправляет в заголовке `Authorization: Bearer ...` во всех следующих запросах.

**Тело запроса**

```json
{
  "email": "ivan@example.com",
  "password": "MyPass123"
}
```

**Ответ 200**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer",
  "user": { "id": 3, "email": "ivan@example.com", "name": "Иван", "is_author": true }
}
```

**Ошибки**

- 401: неверный email или пароль

#### GET `/auth/me`

Кто может: **Вошедший**  ·  Успешный код: **200**

Данные текущего пользователя. Фронтенд вызывает при загрузке страницы, чтобы узнать, вошёл ли пользователь и какая у него роль.

**Ответ 200**

```json
{
  "id": 3,
  "email": "ivan@example.com",
  "name": "Иван",
  "is_author": true
}
```

**Ошибки**

- 401: токен отсутствует или недействителен

### 3.2. Составитель: свои опросы и тесты

#### GET `/my/forms`

Кто может: **Составитель**  ·  Успешный код: **200**

Список всех своих опросов и тестов (черновики и опубликованные). По `public_code` фронтенд строит ссылку для участников.

**Ответ 200**

```json
[
  {
    "id": 7, "is_test": false, "title": "Опрос о поступлении",
    "is_published": true, "requires_login": false, "public_code": "k3x9a2",
    "attempts_count": 12,
    "created_at": "2026-11-01T10:00:00", "published_at": "2026-11-02T09:30:00"
  },
  {
    "id": 8, "is_test": true, "title": "Контрольная по математике",
    "is_published": false, "requires_login": true, "public_code": "m7p2qd",
    "attempts_count": 0,
    "created_at": "2026-11-03T01:15:00", "published_at": null
  }
]
```

**Ошибки**

- 401: не вошёл
- 403: пользователь не составитель

#### POST `/forms`

Кто может: **Составитель**  ·  Успешный код: **201**

Создаёт пустой черновик и случайный `public_code`. Тип (`is_test`) выбирается один раз и потом не меняется. Новая форма сразу получает один пустой блок без названия (и опрос, и тест).

**Тело запроса**

```json
{
  "is_test": true,
  "title": "Контрольная по математике"
}
```

**Ответ 201**

```json
{
  "id": 8,
  "is_test": true,
  "title": "Контрольная по математике",
  "is_published": false,
  "requires_login": false,
  "public_code": "m7p2qd",
  "blocks": [ { "key": "b30", "title": null, "questions": [] } ]
}
```

**Ошибки**

- 422: пустое название

#### PUT `/forms/{id}`

Кто может: **Владелец формы**  ·  Успешный код: **200**

Сохраняет всю форму одним запросом. Сервер удаляет прежнее содержимое черновика и записывает присланное. Новым блокам, вопросам и вариантам фронтенд даёт временные ключи (любые уникальные строки), условия ссылаются на эти ключи, а сервер расставляет настоящие номера. Допустимо только для черновика. Признак `is_test` в запросе не передаётся. Пример для опроса.

**Тело запроса**

```json
{
  "title": "Опрос о поступлении",
  "description": "Короткий опрос для абитуриентов",
  "requires_login": false,
  "max_attempts": null,
  "take_by_blocks": true,
  "allow_free_navigation": true,
  "shuffle_answer_options": false,
  "completion_message": "Спасибо, что ответили на вопросы!",
  "blocks": [
    {
      "key": "b1", "title": "О вас", "condition": null,
      "questions": [
        {
          "key": "q1", "text": "Вы проживаете в столице?", "type": "single",
          "is_answer_required": true, "image_id": 4, "condition": null,
          "options": [ { "key": "o1", "text": "Да" }, { "key": "o2", "text": "Нет" } ],
          "finish_rules": [
            {
              "key": "r1", "message": "Опрос только для жителей столицы. Спасибо за ответ!",
              "condition": {
                "match_all": true,
                "items": [ { "question": "q1", "operator": "chosen", "option": "o2" } ]
              }
            }
          ]
        }
      ]
    },
    {
      "key": "b2", "title": "О поступлении", "condition": null,
      "questions": [
        {
          "key": "q5", "text": "Отвечайте, пожалуйста, честно.", "type": "info",
          "condition": null
        },
        {
          "key": "q2", "text": "Какие вузы вы рассматриваете?", "type": "multiple",
          "is_answer_required": false,
          "options": [ { "key": "o3", "text": "МГУ" }, { "key": "o4", "text": "МФТИ" } ],
          "condition": {
            "match_all": true,
            "items": [ { "question": "q1", "operator": "chosen", "option": "o1" } ]
          }
        }
      ]
    }
  ]
}
```

**Ответ 200**

Та же структура, что в ответе на GET /forms/{id}: форма с настоящими номерами. Ключи заменяются на b21, q101, o301 и т. д., фронтенд подменяет ими временные.

**Условия в запросе (только опросы)**

- `condition` имеет вид {match_all, items}. match_all равно true: должны выполняться все условия; false: достаточно любого. Сейчас в items лежат только простые условия; позже в items можно будет класть такие же объекты {match_all, items} для вложенных групп.
- Операторы: `chosen`, `not_chosen` (нужен `option`), `equals`, `contains` (нужен `text_answer`), `answered`, `not_answered`.
- Условие блока или вопроса может ссылаться только на вопрос, который стоит раньше по порядку (разрешены ранние вопросы того же блока), и не на вопрос типа info. Порядок «раньше/позже» определяется парой (позиция блока, позиция вопроса в блоке): позиция вопроса отсчитывается внутри блока. У тестов условий нет.

**Досрочное завершение и сообщения (только опросы)**

- `finish_rules` у вопроса: список правил {key, message, condition}. Порядок в списке равен порядку проверки (сервер записывает его в `position`); срабатывает первое подходящее правило. `message` необязательно (null), простой текст до 1000 символов.
- `condition` правила имеет тот же вид {match_all, items} и обязателен (правило без условия не имеет смысла). Правило может ссылаться на вопросы, которые стоят не позже вопроса правила: на более ранние и на сам этот вопрос (иначе нельзя написать «если на этот вопрос выбрано Нет, завершить»). На вопросы типа info ссылаться нельзя. У вопроса типа info своих правил нет.
- `completion_message` формы (опрос и тест) и `message` строки шкалы оценок (только тест): простой текст до 1000 символов или null. HTML не поддерживается, текст показывается как есть.
- У тестов `finish_rules` нет.

**Настройки формы**

- Для всех форм: `title`, `description`, `requires_login`, `max_attempts`, `take_by_blocks`, `allow_free_navigation`, `shuffle_answer_options`.
- Только для тестов: `time_limit_minutes`, `show_correct_answers`, `show_results_by_block`, `shuffle_questions`, `grading_scale` (список {min_percent, grade}). Стандартную шкалу 0 — 2, 50 — 3, 70 — 4, 85 — 5 подставляет фронтенд при создании теста; сервер сам её не создаёт.
- У вопросов теста: `points`, `allow_partial_scoring` (для вопросов с несколькими ответами), `correct_text_answers` (список строк для текстового вопроса); у вариантов `is_correct`. Полный пример: GET /forms/{id}. Поля теста (баллы, правильные ответы, шкала, ограничение времени, show_*, shuffle_questions) в запросе для опроса недопустимы (422).
- Баллы `points` целые. У вопросов теста `is_answer_required` не передаётся: пропущенный вопрос даёт 0 баллов; у вопросов опроса он есть.

**Типы вопросов и картинки**

- `type` вопроса: `single` (один ответ), `multiple` (несколько), `text` (текст), `info` (текст без вопроса).
- Вопрос `info` содержит только `text`, необязательную картинку и (в опросе) условие показа. Вариантов, баллов и ответов у него нет, в подсчёт баллов и статистику он не входит.
- Картинка: сначала `POST /images`, затем в вопросе `"image_id": 4`. Один вопрос, одна картинка. В ответах сервера картинка приходит объектом `image` с полями id и url.

**Примеры других условий (каждое в items)**

```json
{ "question": "q3", "operator": "contains", "text_answer": "Москва" }
{ "question": "q4", "operator": "answered" }
{ "question": "q5", "operator": "not_chosen", "option": "o7" }
```

**Ошибки**

- 403: чужая форма
- 409: форма уже опубликована
- 422: условие ссылается на вопрос не раньше по порядку; условие правила досрочного завершения ссылается на вопрос ниже вопроса правила; правила в тесте; сообщение длиннее 1000 символов; задан max_attempts при requires_login = false; поля теста в опросе; у формы нет ни одного блока и т. п. Полнота формы (например, текстовый вопрос без допустимых ответов) при сохранении не проверяется: черновик можно сохранять неполным, проверка идёт при публикации.

#### POST `/forms/{id}/publish`

Кто может: **Владелец формы**  ·  Успешный код: **200**

Публикует черновик. Перед публикацией сервер проверяет форму: есть хотя бы один вопрос; у вопросов с выбором не меньше двух вариантов; в тесте у каждого вопроса есть правильный ответ, у текстового вопроса есть хотя бы один допустимый ответ.

**Ответ 200**

```json
{
  "id": 7,
  "is_published": true,
  "published_at": "2026-11-02T09:30:00",
  "public_code": "k3x9a2"
}
```

**Ошибки**

- 403: чужая форма
- 409: уже опубликована
- 422: форма не прошла проверку (в ответе список проблем)

#### POST `/forms/{id}/copy`

Кто может: **Владелец формы**  ·  Успешный код: **201**

Создаёт копию формы как новый черновик с новым `public_code`. Так делается «редактирование» опубликованной формы: копия правится и публикуется заново.

**Ответ 201**

```json
{
  "id": 9,
  "title": "Опрос о поступлении (копия)",
  "is_published": false,
  "public_code": "t5w8nz"
}
```

**Ошибки**

- 403: чужая форма
- 404: форма не найдена

#### DELETE `/forms/{id}`

Кто может: **Владелец формы**  ·  Успешный код: **204**

**Как считаются показатели**

- Вопросы типа `info` в статистику не входят.
- `started`: все попытки, включая незавершённые; `finished`: попытки с заполненным finished_at; `completion_percent` = finished / started.
- `finished_early` (только опросы): сколько из завершённых попыток закончились досрочно (у попытки заполнено early_finish_rule_id); у тестов null. Такие попытки входят в `finished` и во все остальные показатели.
- `early_finish_rules` (только опросы, иначе null): по каждому правилу, которое сработало хотя бы раз, число попыток, которые оно завершило; в подписи для составителя показываются текст вопроса и сообщение правила. Для вопросов, которые участники не увидели из-за досрочного завершения, `shown` меньше, чем `finished`, и это нормально.
- `median_time_seconds`: медиана значений (finished_at − started_at) по завершённым попыткам, в секундах.
- `shown`: у скольких завершённых попыток вопрос был показан (есть строка в attempt_answers); `skipped`: из них без ответа. `percent` варианта = count / shown × 100; у вопросов с несколькими ответами сумма процентов может быть больше 100.
- `correct_percent` (тесты): доля показанных, где получены все баллы за вопрос. `avg_score_percent` (тесты): сумма баллов за вопрос / (shown × максимум баллов) × 100.
- `blocks` (тесты с двумя и более блоками): `avg_percent` блока = сумма набранных баллов по его вопросам / сумма максимальных баллов этих вопросов × 100, по всем завершённым попыткам. Если у блока нет названия, фронтенд показывает «Блок N».
- `top_answers` (текстовые вопросы): до 20 самых частых ответов; ответы приводятся к нижнему регистру и без лишних пробелов.
- `daily_finished`: завершения по дням; в список входят все дни от первого до последнего завершения, дни без прохождений с нулём.
- Сортировку вопросов теста «сначала сложные» делает фронтенд по `correct_percent`; сервер отдаёт вопросы в порядке формы.

**Опрос и тест**

- У опроса `avg_score`, `avg_percent`, `grade_distribution` и `blocks` равны null; у вопросов нет `correct_percent` и `avg_score_percent`; у вариантов нет `is_correct`.
- У вопросов с выбором есть `options`, у текстовых `top_answers`.

**Ошибки**

- 403: чужая форма
- 404: форма не найдена

Завершает прохождение. Один и тот же запрос для опросов и тестов. Когда у теста истекает время, фронтенд сам отправляет текущие ответы этим же запросом, и засчитывается всё, что участник успел. Анонимный участник добавляет заголовок `X-Attempt-Key` со значением `attempt_key`. Сервер: проверяет, что попытка не завершена и время не вышло; вычисляет видимость вопросов и отбрасывает ответы на скрытые; проверяет обязательные видимые вопросы; для теста считает баллы, процент и оценку; сохраняет ответы. Для опроса сервер сам определяет досрочное завершение: просматривает вопросы сверху вниз, проверяет правила показанных вопросов и при первом сработавшем завершает попытку (раздел 4). Для вопросов с выбором передаётся `option_ids` (номера выбранных вариантов), для текстовых `text`; для `info` ответ не передаётся.

**Сообщение и досрочное завершение**

- `message` есть в ответе всегда (и у опроса, и у теста) и равно первому из заполненных: сообщение сработавшего правила (`early_finish_rules.message`), сообщение полученной оценки (`grading_scale.message`, тест), общее сообщение формы (`forms.completion_message`), иначе «Спасибо за участие!».
- `finished_early` равно true, если попытку завершило правило досрочного завершения (только опросы); у теста всегда false.
- Если правило сработало, ответы на вопросы после вопроса правила сервер отбрасывает, строк в `attempt_answers` для них не создаётся, `attempts.early_finish_rule_id` и `finished_at` записываются. Обязательность проверяется только у вопросов, показанных до завершения.

**Что участник видит после теста (две независимые настройки)**

- Баллы, процент и оценка есть всегда. Баллы целые: дробные частичные баллы за вопрос округляются вниз, поэтому полный балл получает только полностью верный ответ.
- `show_correct_answers` = true: в ответе есть `review` (разбор вопросов с правильными ответами); иначе `review` равно null.
- `show_results_by_block` = true: в ответе есть `block_results` (результат по каждому блоку; показывается при двух и более блоках); иначе равно null.
- `better_than_percent` (только тесты) показывает, лучше скольких процентов участников результат: это доля других завершённых прохождений этого теста с процентом строго ниже. Если других завершённых прохождений меньше 5, поле равно null, и сообщение не показывается.

## 4. Правила показа блоков и вопросов

Участник получает форму целиком вместе с условиями. Фронтенд вычисляет, что показывать, и пересчитывает это при каждом изменении ответа. При завершении то же самое вычисляет сервер. Обе реализации должны работать по одним и тем же правилам:

- Условие блока или вопроса может ссылаться только на вопрос, который стоит **раньше по порядку** (сначала по номеру блока, потом по номеру вопроса). Допускается ссылка на более ранний вопрос того же блока. Так исключаются циклы.
- **Скрытый вопрос считается неотвеченным**, его ответ игнорируется (в том числе в условиях других вопросов).
- Вопрос типа **info** (текст без вопроса) в условиях не участвует, но может иметь собственное условие показа (в опросе). Когда вопрос скрыт, в режиме «один вопрос на экране» он просто пропускается.
- Если **скрыт блок**, скрыты и все его вопросы. Блок, у которого скрыты все вопросы, пропускается (пустая страница не показывается).
- Видимость вычисляется **по порядку сверху вниз**: каждый блок и вопрос смотрит только на уже вычисленные видимые вопросы выше.
- Если участник вернулся назад и изменил ответ (при `allow_free_navigation`), видимость пересчитывается и блок перерисовывается: вопросы с условиями появляются или исчезают сразу, без перезагрузки. Ответ на вопрос, который стал скрытым, фронтенд держит в памяти (если вопрос снова появится, ответ вернётся), но не учитывает.
- **Досрочное завершение** (только опросы). После сработавшего правила все последующие вопросы считаются не показанными: на них нет строк ответов, ответы на них отбрасываются, обязательность не проверяется. Подробности ниже, в разделе «Досрочное завершение опроса».
- При отправке фронтенд **не включает ответы на скрытые вопросы**. Сервер в любом случае повторно вычисляет видимость, отбрасывает лишнее и проверяет обязательность только у видимых вопросов.

### Операторы условий

| Оператор | Для каких вопросов | Что проверяет |
|---|---|---|
| `chosen` | single, multiple | в ответе выбран указанный вариант |
| `not_chosen` | single, multiple | в ответе не выбран указанный вариант |
| `equals` | text | текстовый ответ равен значению (без учёта регистра и лишних пробелов) |
| `contains` | text | текстовый ответ содержит значение |
| `answered` | любые | на вопрос дан ответ |
| `not_answered` | любые | на вопрос нет ответа (в том числе он скрыт) |

### Досрочное завершение опроса

- У вопроса опроса может быть несколько правил (`finish_rules`). Они проверяются по порядку, срабатывает первое, у которого условие выполнено. Условие устроено так же, как условие показа ({match_all, items}, те же операторы).
- Правило может ссылаться на вопросы, которые стоят **не позже вопроса правила**: на более ранние и на сам этот вопрос. Так правило видит только те ответы, которые участник уже дал. На вопросы info ссылаться нельзя.
- Правило проверяется только у **показанного** вопроса (скрытый вопрос считается неотвеченным, и его правила не действуют).
- **Когда проверяется.** При `take_by_blocks` = false сразу после вопроса, когда участник нажимает «Далее»; при true после блока, когда участник нажимает «Далее» на странице блока (правила вопросов блока проверяются по порядку вопросов). Переход по панели номеров или к другому блоку правила не проверяет. Выбор варианта сам по себе опрос не завершает, чтобы не закончить его случайным щелчком.
- Фронтенд проверяет условия по данным из `finish_rules` и, если правило сработало, сам отправляет текущие ответы запросом `POST /attempts/{id}/finish`. Сервер повторно просматривает вопросы сверху вниз и при первом сработавшем правиле завершает попытку: так результат не зависит от фронтенда. Ответ содержит `finished_early` = true и сообщение.
- В режиме блоков вопросы того же блока, что и вопрос правила, остаются показанными и учитываются (весь блок был на экране); не показанными считаются вопросы следующих блоков. В режиме «один вопрос на экране» не показанными считаются все вопросы после вопроса правила.
- Если правило сработало на последнем вопросе, всё равно возвращается `finished_early` = true и сообщение правила: составитель сам решает, нужно ли такое правило.
- Сообщение на странице завершения: первое из заполненных — сообщение правила, сообщение полученной оценки (тест), общее сообщение формы, иначе «Спасибо за участие!». Простой текст, до 1000 символов.

### Что делает сервер при завершении попытки

- Проверяет, что попытка существует, принадлежит этому участнику (токен или ключ попытки) и ещё не завершена.
- Для теста с ограничением времени сравнивает текущее время с началом попытки плюс лимит. Когда таймер доходит до нуля, фронтенд сам отправляет текущие ответы, и засчитывается всё, что участник успел. Сервер принимает такой запрос в пределах 2 минут сверх лимита (запас на задержку сети); позже возвращается 409, и попытка остаётся незавершённой.
- Вычисляет видимые вопросы и отбрасывает ответы на скрытые.
- Для опроса проверяет правила досрочного завершения показанных вопросов (сверху вниз, внутри вопроса по порядку); при первом сработавшем отбрасывает ответы на последующие вопросы и записывает `early_finish_rule_id` в попытку.
- Проверяет обязательные видимые вопросы (только среди показанных до завершения); при пропусках возвращает 422 со списком `missing_question_ids`.
- Выбирает сообщение для страницы завершения (правило, оценка, форма, стандартный текст).
- Для теста считает целые баллы по каждому вопросу (правила подсчёта и округление вниз описаны в документе со схемой БД), затем общий балл, процент и оценку по шкале (в попытке сохраняется строка шкалы).
- Сохраняет по строке в `attempt_answers` для каждого показанного вопроса (даже если ответ пустой; для скрытых вопросов и для info строк нет), выбранные варианты в `attempt_answer_choices`, обновляет `attempts` (время завершения `finished_at`, результат). Отдельного статуса у попытки нет: она завершена, если `finished_at` заполнено.

## 5. Режимы прохождения и перемешивание

Блоки есть и у опросов, и у тестов. Экран прохождения определяют две настройки формы, `take_by_blocks` и `allow_free_navigation`. Они одинаковы у опросов и тестов и приходят в ответе на старт попытки, поэтому прохождение устроено одним и тем же экраном. Четыре сочетания:

| take_by_blocks | allow_free_navigation | Что видит участник |
|---|---|---|
| `true` | `true` | Страница равна блоку: все вопросы блока на экране, отвечать можно в любом порядке. Кнопки «Предыдущая страница» и «Следующая страница», можно переключаться между блоками. |
| `false` | `true` | Один вопрос на экране и панель с номерами вопросов, по которой можно свободно переходить; есть «Назад». |
| `true` | `false` | Страница равна блоку. Закончив блок, участник идёт к следующему кнопкой «Далее», возврат к пройденным блокам недоступен. |
| `false` | `false` | Один вопрос на экране, ответив, участник идёт к следующему. Панели номеров и «Назад» нет, вопросы проходятся последовательно. |

### Особенности

- В режиме «один вопрос на экране» блоки участнику не видны, но условия блоков продолжают действовать: скрытый блок скрывает свои вопросы.
- Обязательные вопросы опроса: в режиме блоков нельзя перейти дальше, пока в блоке остался неотвеченный обязательный вопрос, в режиме «по одному» нельзя пропустить такой вопрос. В тестах обязательности нет.
- Текст без вопроса (`info`): в режиме блоков виден внутри блока; в режиме «один вопрос на экране» показывается над следующим вопросом (если дальше вопросов нет, то над предыдущим). В панели номеров и в нумерации «Вопрос N из M» он не участвует.
- Список блоков и панель номеров показывают только видимые вопросы и блоки, нумерация меняется вместе с условиями.

### Перемешивание

- Перемешивание делает **сервер при старте попытки** (запрос `POST /forms/{id}/attempts`) и отдаёт уже готовый порядок. Фронтенд ничего не перемешивает.
- `shuffle_questions` (только тесты): при `take_by_blocks` = true вопросы перемешиваются внутри каждого блока, порядок блоков не меняется; при false перемешивается весь общий список. В опросах эта настройка недоступна: условия показа ссылаются на более ранние вопросы, и перемешивание бы их сломало.
- `shuffle_answer_options` (опросы и тесты): перемешиваются варианты ответа в вопросах с выбором.
- Обе настройки по умолчанию выключены.
- Для вариантов вроде «Все перечисленные» закрепление в конце не делается. Составителю в конструкторе советуем формулировку «Все варианты верны».

## 6. Диаграммы статистики (Chart.js)

Диаграммы рисует библиотека Chart.js через обёртку `vue-chartjs`. Сервер отдаёт только числа (раздел 3.2, запрос `GET /forms/{id}/stats`), а вид диаграммы выбирает фронтенд:

| Данные | Как показываем |
|---|---|
| `summary` | карточки с числами: начато, завершено, процент завершения, типичное время (медиана), для тестов средний балл |
| `grade_distribution` | вертикальная столбчатая диаграмма: оценки по горизонтали, число прохождений по вертикали; показываются все оценки шкалы, в том числе с нулём |
| `summary.finished_early` | карточка «завершили досрочно» (только опросы) |
| `early_finish_rules` | таблица или горизонтальная диаграмма «какие правила завершили сколько попыток» (только опросы) |
| `daily_finished` | линейный график числа завершений по дням |
| `blocks` | горизонтальная столбчатая диаграмма «средний результат по блокам, %» (тесты с двумя и более блоками): сразу видно, какая тема даётся хуже |
| `questions[].options` | горизонтальная столбчатая диаграмма по каждому вопросу с выбором, подписи «число (процент)»; в тесте верные варианты выделены цветом |
| `questions[].top_answers` | таблица самых частых текстовых ответов |
| `questions[].correct_percent` | полоса или число у вопроса теста; переключатель «по порядку в тесте / сначала сложные» сортирует вопросы на фронтенде |

**Участник.** На итоговой странице теста и при просмотре попытки из истории показывается оценка и, если поле `better_than_percent` не null, сообщение «Вы справились лучше, чем X% участников». История прохождений берётся из `GET /my/attempts`.

## 7. Принятые решения и изменения в базе данных

### Согласовано

- Двузначные значения хранятся булевыми полями: `is_author` (вместо role), `is_test` (вместо type), `is_published` (вместо status), `requires_login` (вместо access), `allow_free_navigation`, `allow_partial_scoring` (вместо scoring_mode), `is_answer_required` (вместо is_required), `match_all` (вместо logic в условиях). У попытки поля status нет, завершённость определяется по `finished_at`; в ответах API это поле `is_finished`.
- Переименования: `take_by_blocks` (вместо show_by_blocks), `shuffle_answer_options` (вместо shuffle_options), `show_results_by_block` (вместо show_block_results), `correct_text_answers` (вместо accepted_answers), `grading_scale` (вместо grade_scale), `text_answer` (вместо text_value), таблицы `question_choices`, `attempt_answers`, `attempt_answer_choices`. Ключи `options`, `option_ids` и `option_id` в JSON остались без изменений (в базе это choice). В JSON ключ шкалы теперь `grading_scale`.
- Типы вопросов и операторы условий вынесены в справочники; в JSON по-прежнему передаются текстовые коды (`single`, `chosen`), сервер сам сопоставляет их с номерами.
- Новый тип вопроса `info` («Текст без вопроса»): нет вариантов, баллов и ответов.
- Картинки к вопросам: одна на вопрос, загрузка отдельным запросом, в вопросе только `image_id`. Картинки в вариантах ответа и видео не поддерживаются.
- Баллы целые, частичные баллы округляются вниз. Оценка в попытке хранится как ссылка на строку шкалы.
- Блоки есть у всех форм; новая форма создаётся с одним пустым блоком без названия. Скрытого блока у теста больше нет.
- Режимы прохождения (`take_by_blocks`, `allow_free_navigation`) одинаковы у опросов и тестов; перемешивание вариантов у обоих типов, перемешивание вопросов только у тестов; всё по умолчанию выключено.
- Участнику после теста можно показывать общий результат, результат по блокам (`show_results_by_block`) и разбор ответов (`show_correct_answers`); это независимые настройки.
- Библиотека блоков: блок копируется (не ссылка), при сохранении в библиотеку создаётся отдельный образец, тип блока равен типу формы, публичность по умолчанию выключена, поиск по названию, описанию и тегам, до 10 тегов на блок, вставку делает фронтенд. Образец ссылается на запись библиотеки через `blocks.library_block_id`, поэтому удаление записи библиотеки удаляет образец.
- Досрочное завершение (только опросы): таблица `early_finish_rules`, несколько правил на вопрос, срабатывает первое подходящее; условие правила хранится в тех же таблицах, что и условия показа; правило может ссылаться на вопросы не позже вопроса правила.
- Сообщения на странице завершения: `forms.completion_message`, `grading_scale.message`, `early_finish_rules.message`; показывается первое из заполненных в порядке «правило, оценка, форма», иначе «Спасибо за участие!».
- Ссылки на формы строятся по случайному коду `public_code`.
- Конструктор сохраняет форму целиком одним запросом PUT; редактировать можно только черновик.
- Участник получает форму целиком вместе с условиями; один запрос finish для опросов и тестов.
- Правила показа блоков и вопросов из раздела 4.
- Формат условия: в конструкторе по временным ключам ({question: "q1", option: "o1"}), у участника по номерам ({question_id: 101, option_id: 301}); группа {match_all, items} допускает вложенность в будущем.
- Если у теста выключено `show_correct_answers`, участник видит только общий результат и оценку: ответ на finish содержит баллы, процент и оценку, а `review` равен null.
- Когда у теста выходит время, фронтенд сам завершает тест и отправляет текущие ответы; засчитывается всё, что участник успел. Сервер принимает запрос в пределах 2 минут сверх лимита (запас на задержку сети).

### Статистика (согласовано)

- Для опросов: сколько прохождений завершено досрочно и какими правилами.
- Составитель: число начатых и завершённых прохождений, процент завершения, типичное время (медиана), для тестов средний балл и распределение оценок; график завершений по дням.
- По вопросам: доля участников по вариантам; для тестов процент полностью верных ответов, средний балл в процентах и сортировка «сначала сложные»; для текстовых вопросов частые ответы.
- В статистику идут только завершённые попытки (кроме показателя «начато»); анонимные прохождения учитываются так же, как остальные.
- Участник: история прохождений, в тесте оценка и сообщение «лучше, чем X% участников» (доля других завершённых прохождений с процентом строго ниже; если других меньше 5, сообщение не показывается).
- Диаграммы строятся библиотекой Chart.js (`vue-chartjs`).

### Отложено

- Экспорт статистики в файл (CSV).
- Совместное редактирование форм (соавторы, защита от перезаписи).
- Генерация форм через ИИ (ключ хранится только на бэкенде, ответ проверяется так же, как тело PUT формы).
- Библиотека отдельных вопросов, закрепление варианта в конце списка.
- Картинки в вариантах ответа, видео в вопросах, автоматическая чистка неиспользуемых картинок.

### Изменения в базе данных, вытекающие из API

- В таблицу `forms` добавлено поле `public_code` (varchar(20), уникальное): случайный код для ссылки.
- В таблицу `attempts` добавлено поле `attempt_key` (varchar(64)): секретный ключ попытки для анонимных участников.
- Для библиотеки добавлены таблицы `library_blocks`, `tags` и `library_block_tags`; блок-образец хранится в `blocks` с пустым `form_id` и заполненным `library_block_id`.
- Добавлены справочники `question_types` и `condition_operators` и таблица `images`. Всего в базе 19 таблиц (см. документ со схемой БД).
- Для досрочного завершения и сообщений добавлены таблица `early_finish_rules`, поля `condition_groups.early_finish_rule_id`, `attempts.early_finish_rule_id`, `forms.completion_message` и `grading_scale.message`.
- Строка в `attempt_answers` создаётся для каждого вопроса, показанного участнику, даже если ответ пустой. Для вопросов, скрытых условиями, и для info строк нет. Так в статистике отличают «пропустил» от «вопрос не показывали».
